# 多语种整理工作台（改点与分part稿自动整理工具）v1.9.5 完整功能说明书

本软件专为多语种三列对照（**第 1 列中文 / 第 2 列英文 / 第 3 列外文**）Word（`.docx`）文稿打造，基于纯标准库深度 OpenXML 排版引擎构建，**免安装、零第三方运行时依赖、不破坏 Word 原生样式与批注**，内置六大核心业务工作台与独立全局配置中心，并支持客户端一键在线检测与热更新。

## 二、启动方式、界面布局与通用交互

### 2.1 启动方式
1. **免安装单文件版（日常办公推荐）**：解压 `ScatteredRevisionTool-Windows-x64.zip`，直接双击运行 **`零散改点整理工具.exe`**（自适应 Windows 100%~200% 高分屏缩放，无需安装 Python）。
2. **源码脚本启动（开发调试）**：双击 `零散改点工具/启动工具.bat`，或执行 `python .\零散改点工具\app_gui.py`。

### 2.2 界面结构
- **左侧导航栏**：按三大业务分组切换 6 个功能板块；底部固定显示 **「检查软件更新」** 按钮，任意窗口高度下均不遮挡。
- **顶部全局状态栏**：左侧显示当前板块标题，右侧精炼展示 `当前模型 | Key 数量 | 黄标连片间隔词数`，点击可直接跳转 **「系统设置」** 或打开 **「语种库」**。
- **上下可拖拽分隔面板**：各工作台的参数区与日志/列表区之间设有分隔条，可按屏幕大小上下自由拉动调节高度。

### 2.3 全局拖拽与实时刷新机制
- **全局拖拽**：支持直接从桌面或资源管理器将 `.docx`、`.txt` 文件或文件夹拖入对应的路径输入框、蓝色虚线拖拽区、文档列表或左侧导航按钮。
- **每次运行实时读取最新文件（防旧缓存）**：
  - 每次点击执行任务均创建全新独立临时工作目录，并实时核验待处理文稿、最新中英底稿、外文总库及查重包的文件修改时间（`mtime`）与字节大小；同名文稿或总库某段修改保存后直接再次运行即可生效，绝不调用过期备份。
  - 界面路径旁同时提供 **「刷新」**、**「刷新总库」**、**「刷新底稿」** 按钮，可随时手动强制重扫校验。

### 2.4 软件在线检查与热更新
- 软件启动后在后台静默检查 GitHub 最新版本；发现新版本时顶部自动弹出蓝色提示条，也可随时点击左下角 **「检查软件更新」**。
- 点击 **「立即下载并自动更新」** 后，程序自动完成下载、**SHA-256 安全完整性校验**、无感替换 `.exe` 并自动重启，**本机保存的加密 API Key 池、常用语种置顶、历史路径与参数设置 100% 完整保留**。

## 三、全局配置：「系统设置」与语种库管理（首次使用必看）

点击左侧导航底部的 **「系统设置」**（或右上角快捷按钮）进入全局配置页：

### 3.1 API 密钥池、通道与模型设置
1. **选择模型**：
   - `Gemini 3.5 Flash Lite (推荐·均衡快速)`（默认推荐，语义分级与跨语种对齐精度高、速度快）
   - `Gemini 3.1 Flash Lite (极速·超低成本)`
2. **接口通道**：
   - `自动识别 (支持混填 Vertex Key 与 Gemini Key)`（默认推荐，自动根据 `AQ.` / `AIza` 前缀走对应通道）
   - 也可手动固定为 `Vertex AI API Key` 或 `Gemini API Key (AI Studio)`。
3. **多 Key 调度策略**：
   - `均衡轮换 + 报错秒切`（推荐：多个 Key 轮流分摊请求，遇超速/额度耗尽毫秒级自动切换下一个 Key）
   - `顺序主备 + 报错秒切`（优先使用第 1 个 Key，报错时自动切备用 Key）
4. **本机加密保存**：默认勾选 **「本机加密记住密钥池 (Windows DPAPI)」**，密钥使用当前 Windows 登录账户硬件级加密存储于本机，拷走配置文件无法在其他电脑解密。
5. **内嵌多行 API Key 编辑器与批量检测**：
   - 每行填写 `1` 个 API Key，支持在 Key 后加 `# 备注`（如 `AIzaSy... # 账号1`）。
   - 点击 **「保存设置」** 立即生效；点击 **「测试连接」** 验证当前首个 Key；点击 **「批量检测全部 Key」** 可并发检测池内所有 Key 的可用性与延迟，并支持 **「一键剔除失效 Key」**。
   - **离线自动兜底**：若未配置 Key、取消勾选 AI 开关或所有 Key 临时限流，程序不会中断报错，而是自动切换至**本地位置估算引擎**完成标色输出。

### 3.2 改点高亮与排版规则参数
- **两处黄色高亮自动连片最大间隔词数**：
  - 支持人工输入数字或上下微调（范围 `0 ~ 20`，**默认值为 `3`**）。
  - **作用**：同一段落内，当两处黄色（`UP`）高亮之间夹着的未标色英文单词数 `≤` 设定值（含跨句号连接词，如 `. Thus,`）时，自动将中间间隔连成一整片黄色高亮，避免译者看到碎成一截一截的高亮；若设为 `0` 则关闭自动连片。

### 3.3 常用语种置顶（`★`）、最近使用（`⏱`）与标准字体库
- 点击 **「管理常用语种与标准字体库...」**（或右上角 **「语种库」**）：
  - 支持新增、编辑、删除语种代号（如 `PL` 波兰语、`BG` 保加利亚语、`TH` 泰语、`FR` 法语等）、识别关键词及三档标准字号（大标题 / 二级标题 / 正文）。
  - **设为常用语种**：选中任意语种后，勾选 **「设为常用语种（下拉框置顶）」**、双击该行或点击 **「切换选中语种常用置顶」**，即可打上 `★` 标记。
- **所有板块下拉框智能排序**：
  1. `AUTO - 自动根据路径/文档识别`
  2. `★` 已收藏的常用语种（置顶）
  3. `⏱` 最近使用过的语种（自动记忆排前）
  4. 其余全部语种（按字母排序）

## 四、板块 1：「零散改点整理」完整操作指南

适用于日常带有**浅蓝底纹（`#DEEAF6`）或粉红底纹（`#F2CEED`）**选段标记的零散改点稿件，一键输出可直接发给译者的定稿与留底稿。

### 4.1 操作步骤
1. **选择待整理文档 (`.docx`)**：拖入或浏览选择待处理稿。
   - **自动兼容两列稿**：若原稿仅有「中文 + 英文」两列，程序会自动将其扩展为横向 A4 三列表格再提取对比。
   - **同文档重复中文段自动合并底纹**：若同一份汇总需求稿中某段中文出现了两次（例如前一次标了前半段颜色、后一次标了后半段颜色），程序会自动把两段的底纹颜色合并到同一段，并删除多余重复段。
2. **选择对应语种总库目录**：拖入或浏览选择该语种《七卷书》三语总库文件夹（程序后台多线程建立增量索引，支持无标题全文极速匹配，自动跳过 `~$` 临时文件与 `标记结果/答案/初筛` 目录）。
3. **选择输出保存目录**：默认自动定位到待整理文档同级的输出目录，可点击 **「打开目录」** 随时查看结果。
4. **（可选）核对最新中英底稿**：
   - **适用场景**：待处理文稿制作时间较早，中英文文字与最新定稿中英底稿存在出入时使用。
   - **操作方法**：勾选 **「核对最新中英底稿：」**，点击 **「选文件...」**（指定单本最新中英底稿，如 `最新中英稿 01《神的显现与作工》20261116【标you】.docx`）或 **「选文件夹...」**（指定最新中英底稿库目录）。
   - **无损保格式效果**：程序先从最新中英底稿提取匹配段落，**仅原地更新待处理稿第 1、2 列的文字值，100% 保留待处理稿原有的字体（如宋体/Georgia）、字号、蓝/红字体颜色以及浅蓝/粉红/白底背景底纹（绝不覆盖底色、不产生白洞断层）**，同时在输出目录生成一份 **`{原文档名}{YYYYMMDD}更新.docx`**（如 `待处理稿子-未更新20261118更新.docx`），并自动以这份更新稿继续执行后续提取与对比！
   - 若未勾选或未填路径，则直接按原待处理稿正常处理。
5. **（可选）关联「未入库改点包」查重**：勾选并指定未入库改点包文件夹后，输出时会自动对照未入库包按第 1 列中文四级查重，导出《查重结果明细报告》，并在发给译者的版本中自动剔除重复段落、重算字数。
6. **确认选项与命名模式**：
   - **目标语种**：可保持 `AUTO` 自动识别，或手动指定语种代号（如 `PO`、`PL`、`BG`）。
   - **三语列宽自动拉齐**（默认勾选）：根据三列文字密度智能微调列宽比例，让中/英/外三列段落高度尽可能对齐美观。
   - **同时输出完整留底版与无改点版**（默认勾选）：同时生成给译者的精简版与保留全部行的留底版。
   - **对比标记高亮颜色**（默认勾选）：勾选时中/英/外三列同步标色；**取消勾选时仅提取第 3 列并输出第 2 列英文修订痕迹（`<w:ins>`/`<w:del>`），不标任何高亮底色**。
   - **导出对比前的「提取三语原稿」供核对**（默认勾选）：额外导出一份刚从总库提取填入第 3 列、尚未做英文对比修订的原始三语文档，方便人工对照原库核查。
   - **命名模式**：
     - **零散标准命名**：以 `God's words` 为主名称；若在右侧填写关键词（如 `15P`），则生成 `SW_God's words in 15P_(UP 96 words)_20261118.docx`；关键词留空则为 `SW_God's words_(UP 96 words)_20261118.docx`。
     - **自定义 / 原文档名**：保留原文件名或按输入名称命名。
7. 点击 **「一键输出定稿」** 等待进度条完成即可。

### 4.2 输出文件说明（单篇平铺规则）
单次处理 1 份待整理文档时，所有结果文件**直接平铺在输出目录根目录**（不套多余子文件夹）：
- **给译者版（主交付稿）**：`{语种}_{名称}_(UP X words, RV Y words)_{YYYYMMDD}.docx`
  - **逐行彻底剔除无改点段落**：即使一个大表格内有几十行，只要某一行无改点就会被精准移除，仅保留真正有改点的行发给译者；
  - **`0` 词自动省略**：若 `RV = 0`，文件名仅显示 `(UP X words)`；若 `UP = 0`，仅显示 `(RV Y words)`；
  - **文档顶部自动插入高亮说明行**：既有黄又有青时插入两行说明；仅有黄色时只插 `Yellow highlighted parts need to be updated.`；仅有青色时只插 `Blue highlighted parts need to be reviewed.`。
- **完整留底版**：`{语种}_{名称}_完整留底版_(...)_{YYYYMMDD}.docx`（保留原文档全部表格与未改动行，供组内留档核查）。
- **提取三语原稿**（勾选时导出）：`{语种}_{原名}_提取三语原稿_{YYYYMMDD}.docx`。
- **最新底稿更新稿**（勾选核对最新中英底稿时导出）：`{原名}{YYYYMMDD}更新.docx`。

## 五、板块 2：「全篇改点整理」完整操作指南

适用于整篇或成批神话篇目的全篇对比整理，提供**两种工作模式**自由切换：

### 5.1 模式 A：按标题列表提取篇目（默认勾选）
1. **输入待提取标题**（一行一个标题，或点击 **「导入标题文档 (.docx / .txt)...」** 批量导入）：
   - 支持纯标题：`实行真理才是有实际`
   - 支持带单编号或双编号、括号后缀与末尾标点的标题，例如：
     - `3-1-35 实行真理才是有实际`
     - `3-1-37 030 神的作工像人想象得那么简单吗？`
     - `3-1-39 032 七雷巨响——预言国度的福音将扩展全宇（审判）`
   - **智能检索与前缀保留规则**：检索时自动剥离前导序号（`3-1-39 032`）、括号尾注（`（审判）`、`（话）`、`【标you】`）及句末问号/感叹号进行高精度匹配；输出英文命名时**自动将输入的编号前缀保留在语种代号之后**，如：
     `PL_3-1-39 032_Seven Thunders Peal—Prophesying That the Gospel of the Kingdom Shall Spread Throughout the Universe_(UP 96 words)_20261118.docx`
2. **兼容单篇文档与多篇合集文档**：无论「最新中英底稿目录」或「外文三语总库目录」里是一篇一个 `.docx`，还是多篇汇总在一本大书 `.docx` 里，程序均会自动定位对应标题并精准拆出该篇标题与正文行（若遇到同名多篇候选，会自动弹出消歧窗口供勾选确认）。

### 5.2 模式 B：现成双文件夹直连对比（取消勾选「按标题列表提取篇目」）
- **适用场景**：手头已经整理好一一对应的两个文件夹——「最新中英底稿包」与「外文三语文件包」，无需再输入标题列表。
- **操作方法**：取消勾选顶部的 **「按标题列表提取篇目」**，分别指定「最新中英底稿目录」和「外文三语总库目录」，点击开始执行。
- **配对与命名规则**：程序按文件名自然顺序逐篇配对对比，输出文件名直接采用**最新中英底稿原文件名**，如最新中英底稿为 `3-1-35 实行真理才是有实际.docx`，输出为：
  `PL_3-1-35 实行真理才是有实际_(UP 96 words)_20261118.docx`

### 5.3 英文无改点自动过滤汇总 & 智能分文件夹规则
- **英文无改点篇目汇总报告**：全篇批量对比中，若某篇中英底稿与外文库英文完全一致（`UP = 0` 且 `RV = 0`），程序**自动跳过导出该篇的给译者版/完整版对比稿**，并在任务结束时统一生成一份 **`全篇对比_英文无改点篇目汇总报告_{YYYYMMDD}.docx`**，清晰列出所有无改点篇目及来源文件，避免空改点文件混入译者包。
- **智能归档规则（1 篇平铺 / 多篇分夹）**：
  - 当本次仅处理 **1 篇** 时：结果文件直接**平铺在输出目录根目录**，不建子文件夹；
  - 当本次批量处理 **≥ 2 篇** 时：自动在输出目录下建立四大分类文件夹整洁归档：
    1. `给译者版/`（仅保留首行标题行 + 有改点段落行，带顶部高亮说明行）
    2. `完整留底版/`（保留整篇全部段落行）
    3. `中英最新底稿包/`（本次提取出的最新中英单篇原稿，供核对）
    4. `外文三语原稿包/`（本次从外文总库提取出的对比前三语单篇原稿，供核对）

## 六、改点标色标准、三列同步与精细边界规则速查

### 6.1 三列处理与高亮颜色映射表

| 表格列 | 修订痕迹（Track Changes）处理 | `UP`（局部更新）高亮色 | `RV`（整句重翻审核）高亮色 | 格式与颜色保真规范 |
| :--- | :--- | :--- | :--- | :--- |
| **第 1 列（中文）** | **自动全部接受修订**（清除旧删除线文字，保留最新中文正文） | **黄色** (`yellow`) | **青色** (`cyan`) | 与第 2 列改点片段语义同步标色；保留原中文段落格式 |
| **第 2 列（英文）** | **全程保留 `<w:ins>` / `<w:del>` 修订痕迹**（黄/青均不接受修订） | **黄色** (`yellow`) | **青色** (`cyan`) | **逐字符保留原稿内联蓝字（`#0000FF` 经文）与红字（`#FF0000`）**，防段首蓝字染蓝整段、防经文丢色 |
| **第 3 列（外文）** | 无修订痕迹（保持总库提取原貌） | **黄色** (`yellow`) | **浅灰** (`lightGray`) | **100% 保留总库原有的对齐方式（居中/两端对齐等）、字体、字号与粗细**（原稿不加粗绝不误变加粗），不额外拆段换行 |

> **提示**：若取消勾选「对比标记高亮颜色」，第 2 列仍保留完整英文修订痕迹、第 3 列仍正常提取保格式，三列均不添加上述高亮底色。

### 6.2 人称代词角标消歧自动过滤（`you ⇄ you(s) / you(pl)`）
- 若仅在同词根代词（`you` / `your` / `yours`，同大小写）上**单纯增补或去掉** `(s)` / `(pl)` 角标（例如 `you` → `you(pl)` 或 `you(s)` → `you`），视为内部消歧标注，**不算实质改点，直接静默接受为最新文本，不留修订痕迹、不标高亮、不计字数**。
- 若发生**单复数实质互改**（例如 `you(s)` ⇄ `you(pl)`），正常保留修订并标黄计入 `UP`。

### 6.3 五条高亮边界精细规则
1. **纯标点 / 引号 / 大小写微调 → 3 词窗口**：仅改动标点符号或首字母大小写（英文单词未变）时，第 2 列与第 3 列同步仅标记改动点附近约 **3 个词**为黄色，不扩大到整分句。
2. **句号/逗号改冒号的严格起标边界**：
   - **纯标点改为冒号**（如 `flower.` → `flower: Flowers...`）：**绝不向前扩展整句**，严格从冒号 `:` 开始往后标记黄色；
   - **单词连带修改为冒号**（如 `flower that` → `flower:`）：向前扩展覆盖整句开头。
   - **括号内局部修改**：仅在括号 `(...)` 内起止标黄，不波及括号外正文。
3. **半句局部改写 vs 整句重翻（严格控制青色 `RV`）**：
   - 长句中若另一分句（≥ 5 词）未动，仅一侧分句改写（如 `as far as man is concerned` → `when it comes to man`），在连词/分句处断开，**仅对修改半句标黄色（`UP`）**；
   - 仅当前后实词重合极少（≤ 2~3 词）、整句句式推倒重来时，才按完整句号边界标为青色（`RV`）。
4. **黄色高亮短间隔自动连片（可在「系统设置」调节）**：同一段内两处黄色高亮之间未标色英文词数 **≤ `N` 词**（默认 `3` 词，含跨句号短连接词）时，自动连成一片黄色。
5. **长段落零碎大改自动升格整段青色（`RV`）**：当长段落（≥ 4 句）几乎全段被改得支离破碎（未改句 ≤ 2 句且 ≥ 75% 句子密集改动，“整段花掉”）时，自动升格为整段连续青色（`RV`），方便译者顺畅通读重审。

## 七、板块 3：「改点稿查重」（未入库改点包四级查重）

用于将整理好的待发改点稿与「未入库改点包」（尚在译者手中翻译、未回库入总库的历史改点稿集合）做比对，防止同一改点重复派发计费。

1. **导入待查重文档**：拖入单个或多个已整理的改点稿 `.docx`（或整个文件夹）。
2. **设置「未入库改点包目录」与输出目录**。
3. **四级中文匹配逻辑**：提取待查重稿**第 1 列中文段落**，在未入库改点包所有 `.docx` 中按以下四级优先级检索：
   `① 整段精确匹配` → `② 段首长句匹配` → `③ 段尾长句匹配` → `④ 带高亮/底纹着色核心片段匹配`
4. **输出结果**：
   - 单独导出一份横向 A4 **`查重结果明细报告_{YYYYMMDD}.docx`**，逐条列出待处理稿的哪个段落与未入库包中**哪份文档的哪一段**发生了重复及匹配级别；
   - 勾选 **「同时导出剔除重复段落后的发译者定稿」**（默认勾选）时，自动生成排除了重复段落的干净发译者稿，并**自动重新统计剩余 `UP` / `RV` 英文词数、更新文件名与顶部说明行**。

## 八、板块 4：「英文字数统计」（算词与规范重命名）

当人工在 Word 中手动调整过某份改点稿的黄色/青色高亮范围后，可用本板块一键重新算词、更新开头说明行并按规范重命名（纯离线毫秒级完成）。

1. **统计口径**：
   - 严格只统计表格 **【第 2 列（英文列）】** 接受修订态正文的英文单词数（正常 `<w:t>` + 新增 `<w:ins>` 计入，已删除 `<w:delText>` 与标点符号自动排除；第 1 列中文与第 3 列外文绝不影响字数统计）。
   - `UP` = 第 2 列黄色（`yellow`）高亮词数；`RV` = 第 2 列青色（`cyan`）高亮词数。
   - **`0` 词自动省略**：`UP = 0` 或 `RV = 0` 时，文件名括号内自动不体现为 `0` 的那一项（如 `_(UP 96 words)_`）。
2. **三种文档命名规则**：
   - **保留原文档名**：保留原主文件名，仅更新或加上语言前缀、字数括号与日期。
   - **全篇改点（取首行第 2 列加粗英文标题）**：自动提取表格第 1 行第 2 列的加粗英文标题作为主文件名，例如：
     `SW_Christ Does the Work of Judgment With the Truth_(UP 96 words, RV 55 words)_20261118.docx`
   - **零散改点（`God's words [in 关键词]`）**：主名称固定以 `God's words` 开头；若输入关键词（如 `15P`），自动接在 `in` 后面生成：
     `SW_God's words in 15P_(UP 96 words)_20261118.docx`
3. **同步更新开头高亮说明行**（默认勾选）：自动检测文档实际存在的黄/青高亮种类，在文档开头表格前精准写入或更新：
   - 含青色高亮时：`Blue highlighted parts need to be reviewed.`
   - 含黄色高亮时：`Yellow highlighted parts need to be updated.`
   （若仅有一种颜色，则只保留对应的一行说明。）
4. **保存方式**：支持 **「直接就地更新原文档（推荐）」** 或 **「另存副本到指定文件夹」**；在下方预览表格核对无误后点击右下角 **「计算字数并立即更新文件名」** 即可。

## 九、板块 5：「分part稿整理/合并」（合并排版与语系标准字体）

专为分篇翻译回稿（如 `Part 1`、`Part 2`... 或同一文档内含多段 `Part` 小表格的弟兄交通/神话定稿）设计的一键合并与出版级规范排版工具：

1. **两种分篇结构自动识别**：
   - **多文件合并**：拖入整个分篇文件夹或多个 `Part 1..N.docx`，自动按分篇序号自然排序合并（自动去重各分篇重复主标题）。
   - **单文件内多 Part 表格合并**：单个 `.docx` 内被多段 `Part` 标题切开的多个表格，自动合并为统一三列大表，并自动修复异常 `gridSpan` 防止列错位。
2. **自动清洁与版面统一**：
   - 统一设置为 **横向 A4 页面**，关闭修订模式并接受残留修订，一键清除全篇批注（Comments），清理句尾多余空格与单元格底部多余空行。
3. **第 2 列 → 第 3 列样式精准镜像同步**：
   - **蓝字（`#0000FF`）与加粗独立判断同步**：严格依据第 2 列英文样式镜像同步到第 3 列外文——整段蓝但未加粗则第 3 列仅标蓝不加粗；段内局部圣经引文蓝字/加粗支持 AI 跨语种精准定位（绝不误加粗普通叙述文字）。
   - **可选同步红色字体（`#FF0000`）**：勾选后可将第 2 列红字同步至第 3 列（适用于神话定稿；若第 3 列已有人工标红则自动保护跳过）。
   - **括号出处字号自动识别**：自动区分圣经引文括号出处与神话书名括号出处，套用对应层级字号。
4. **引号规范化与《各语系字体》标准套用**：
   - 支持自动规范化为弯引号 `“”` `‘’`（**法语自动保护并保留书名引号 `« »`**），也可选择强制弯引号或保持原引号不改。
   - 自动按目标语种套用内置《各语系字体》标准（覆盖 50+ 语种的专属字体与大标题/二级标题/正文三档字号，如泰语 `Angsana New` `18 / 16 / 14 pt`、西欧语系 `Times New Roman` 等，可在「语种库」中自由查阅或微调）。
5. **三种输出方式**：
   - `仅输出各单篇` / `仅输出汇总合并总文档（去掉 Part 序号，自动输出标准三语命名）` / `各单篇 + 汇总合并总文档同时输出`。

## 十、常见问题与排障指南（FAQ）

1. **问：我刚刚修改了总库里的某篇文档（或修改了待处理稿），需要重启软件或删缓存吗？**
   - **答**：不需要。v1.8.0 每次点击运行都会创建全新临时工作目录，并实时对比磁盘文件的修改时间与大小自动重扫变更文件；您也可以随时点击路径框右侧的 **「刷新」** / **「刷新总库」** / **「刷新底稿」** 按钮立即校验。
2. **问：Word 打开生成的文档还会弹出“发现无法读取的内容”吗？**
   - **答**：已彻底根治。底层 OpenXML 引擎在保存前会对所有修订 ID、批注引用关系、`w:rPr` 子标签严格顺序（ECMA-376 标准）与表格网格做完整性归一化校验，Word 可直接无弹窗顺畅打开。
3. **问：没有配置 API Key 或者网络不通时能用吗？**
   - **答**：完全可以。「改点稿查重」与「英文字数统计」本身就是 100% 纯离线功能；「零散改点整理」、「全篇改点整理」与「分part稿整理/合并」在无 Key 或 Key 超额时会自动无缝降级为本地规则与位置估算引擎完成全部流程。配置 Gemini / Vertex Key 后则可获得更精准的句意 `UP/RV` 判定与跨语种词组级对齐。
4. **问：换新版本时，我配置的十几个 API Key 和常用语种会丢吗？**
   - **答**：不会。所有个人设置与加密密钥均独立保存在当前系统用户目录中，无论是通过软件左下角「检查软件更新」自动升级，还是手动下载新版 `.exe` 覆盖原文件，原有配置与收藏语种均自动继承。
